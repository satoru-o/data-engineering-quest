# quest-02: アクセスログの型そろえ

文字列のまま届いたアクセスログに、集計できる型を付ける。

> 15分。書き換えるのは3行の右辺だけだ。
> 書き方は [../CHEATSHEET.md](../CHEATSHEET.md) にすべて載っている。見ながら書いてよい。

## 状況

Web サーバのアクセスログが、日次で CSV になって届く。
これを DWH に載せて「時間帯ごとの 5xx 率」「遅いパスの上位」を出したい、
という話になっている。

ところが CSV は全部の列が文字列だ。
`pd.read_csv()` に通した直後は、こうなっている。

```
ts        object      "2026-01-05T00:12:03Z"
path      object      "/items/1001"
status    object      "200" と "-" が混ざっている
dur       object      "1.2s" のように単位が付いている
```

この形では時間帯で切ることも、5xx を数えることも、遅い順に並べることもできない。
比較も集計も、まず型が付いていることが前提になる。

汚れの出どころは3つで、それぞれ理由がある。

| | |
|---|---|
| `ts` | ログの標準形。末尾の `Z` は「UTC である」という意味を持っている |
| `status` | 応答が返る前にタイムアウトした行は、ステータスが無いので `-` で埋まる |
| `dur` | 人が読むためのログなので、数字に単位が付いたまま出ている |

送信元は直してもらえない。取り込み側で吸収する。

## ミッション

`work/solve.py` の TODO を3つ埋め、3つの列に正しい型を付ける。

| | | |
|---|---|---|
| 問1 | `ts` | `datetime64[ns, UTC]` |
| 問2 | `status` | `Int64` (`-` は欠損) |
| 問3 | `dur` | `float64` (秒。`"1.2s"` → `1.2`) |

1問につき1行。読み込みと書き出しは書いてあるので触らなくてよい。

> [!IMPORTANT]
> 問2 は `int64` ではなく `Int64` だ。頭が大文字のほうは欠損を持てる整数型で、
> 小文字の `int64` は持てない。`-` の行があるので小文字では型を付けられない。

## 参考解答

<details><summary>答え</summary>

```python
df["ts"] = pd.to_datetime(df["ts"], utc=True)
df["status"] = pd.to_numeric(df["status"], errors="coerce").astype("Int64")
df["dur"] = df["dur"].str.removesuffix("s").astype("float64")
```

`utc=True` を付けないと `Z` が捨てられて tz-naive になる。
`errors="coerce"` は「変換できなかったものを欠損にする」指定で、`-` がこれで `NA` になる。
`removesuffix` の代わりに `.str.rstrip("s")` や `.str[:-1]` でも通る。

判定は値を見ているので、同じ結果になる書き方であれば何でも正解になる。

全文は [solution/solve.py](solution/solve.py) にある。

</details>
