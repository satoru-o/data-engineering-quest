# quest-02: アクセスログの下ごしらえ

文字列のまま届いたアクセスログを、集計できる形に整える。

> **毎回ちがう3問が出る。** 出題は [../CHEATSHEET.md](../CHEATSHEET.md) の節に対応していて、
> 節名がそのまま問題文に `[ ]` で出る。見ながら書いてよい。1問1行で書ける。

## 状況

Web サーバのアクセスログが、日次で CSV になって届く。
これを DWH に載せて「時間帯ごとの 5xx 率」「遅いパスの上位」を出したい、
という話になっている。

ところが CSV は全部の列が文字列だ。
`pd.read_csv()` に通した直後は、こうなっている。

```
ts        object      "2026-01-05T00:12:03Z" や "2026-01-05T09:12:03+09:00"
path      object      "/items/1001"
status    object      "200" と "-" が混ざる
dur       object      "1.2s" のように単位が付いている
bytes     object      "1,234" のように桁区切りが入っている
user_id   object      取れなかった行は空
```

この形では時間帯で切ることも、5xx を数えることも、遅い順に並べることもできない。
比較も集計も、まず型が付いていることが前提になる。

送信元は直してもらえない。取り込み側で吸収する。

## ミッション

`work/solve.py` の `ansN = ...` の右辺を3つ埋める。

**出題は毎回変わる。** 9つの節から、必ず違う節を3つ選んで出す。
データも毎回作り直されるので、前回の答えをそのまま使うことはできない。

| 出題される節 | |
|---|---|
| 型を直す / 文字列 / 欠損 / 重複 | 汚れを落とす側 |
| 行を選ぶ / 列を作る・直す / 日時 | 形を変える側 |
| 集約 / 結合 | 使える形にまとめる側 |

`CHEATSHEET.md` の残り4節 (まず形を見る、読む / 書く、よくある落とし穴) は出題しない。
見るだけの操作だったり、問題の外側だったりして、採点にならないからだ。

## 手順

```bash
mk quest-02             # 問題を配って採点する (初回はこれだけでよい)
```

`quest-02-access-log-transform/work/solve.py` を開いて右辺を埋め、
もう一度 `mk quest-02` を叩く。これを繰り返すだけだ。

| | |
|---|---|
| `mk quest-02` | 採点する。**問題は引き直さない** |
| `mk quest-02-new` | 別の3問を引く (今の答えは消える) |
| `mk quest-02-reset` | 問題はそのままで `solve.py` だけ白紙に戻す |
| `mk quest-02-answer` | 今出ている3問の参考解答を出す |
| `SEED=1234 mk quest-02-new` | seed を指定して同じ問題を再現する |

> [!IMPORTANT]
> `mk quest-02` は問題を引き直さない。直している最中に問題が変わったら、
> 直しようがないからだ。引き直したいときだけ `mk quest-02-new` を叩く。

> [!NOTE]
> `work/` も `data/` も git 管理外だ。自分の答えはコミットされない。
> 採点のたびに `seed=NNNN` が出るので、`SEED=NNNN mk quest-02-new` で
> 気に入った問題をあとから呼び戻せる。

> [!TIP]
> 思い出そうとして止まるのは時間の無駄だ。[../CHEATSHEET.md](../CHEATSHEET.md) を
> 開いたまま書く。`[ ]` に出ている節名が、そのままチートシートの見出しだ。

## 判定

`check.py` が `work/solve.py` を実行し、`ans1` `ans2` `ans3` を見る。
3問すべて採点して出すので、途中まででも進みが分かる。

```
問1 [文字列] .................. OK
問2 [型を直す] ................ NG
       ts を datetime64[ns, UTC] にした Series (末尾の Z と +09:00 が混ざっている)
       → dtype が違う   期待: datetime64[ns, UTC]   実際: object
       CHEATSHEET.md の「型を直す」を見ること
問3 [集約] .................... NG
       path ごとの件数の Series (添字が path、値が件数)
       → 行数が違う   期待: 6行   実際: 24行
       CHEATSHEET.md の「集約」を見ること

3問中 1問。work/solve.py を直してもう一度 mk quest-02   (seed=42)
```

**判定は値を見ている。同じ結果になる書き方であれば何でも正解になる。**
`.str.removesuffix("s")` でも `.str.rstrip("s")` でも `.str[:-1]` でも通る。

添字 (index) の扱いには規則がある。

| | |
|---|---|
| 答えが DataFrame | 列名と値で比べる。**添字は見ない** |
| 答えが Series | 値で比べる。**添字が連番でないときだけ添字も見る** |

行を絞ったあとの添字が飛び飛びでも落とさない、ということだ。
`.reset_index(drop=True)` の付け忘れで失点しても何も学べない。
一方で `df.groupby("path").size()` の添字 `path` は答えそのものなので、こちらは見る。

FLAG は無い。15分の問題に隠し玉は要らない。

## データ

`data/access_log.csv` — 15〜30行。`mk quest-02-new` のたびに作り直される。

**引かれた問が必要とする汚れだけを載せている。** 重複の問が出なければ重複行は入らないし、
結合の問が出たときだけ `data/screens.csv` (path → 画面名のマスタ) が現れる。
関係のないところで引っかかって時間を取られないようにするためだ。

## 扱わないこと

問題を1行で解くところまでで終わる。パイプラインとして繋ぐことはしない。
3問は互いに独立していて、**前の問を間違えても後ろに影響しない**
(集約や結合は行数も列も変えてしまうので、繋ぐと部分点が出せなくなる)。

文字コードの判別や、訂正データの処理順は入れていない。そちらは
[quest-01](../quest-01-raw-ingest/) が丸ごと扱っている。

## 前提

ホストに `uv` が要る。**このクエストだけの例外**で、他の教材はすべて Docker の中で
完結する。15分で終わる問題にイメージのビルド待ちを付けたくなかったためだ。
`mk quest-02` は `uv` が無ければその場で止まって案内する。

Docker は使わないので、ポートも上がらない。

## 中身

| | |
|---|---|
| `questions.py` | 出題バンク (9節 × 2問) とデータ生成。**全問の答えが入っているので開かない** |
| `gen.py` | seed を決め、3問を引き、データと `work/solve.py` を作る |
| `check.py` | `work/solve.py` を runpy で動かし、`ansN` を採点する |
| `answer.py` | 今の3問だけの参考解答を出す (`mk quest-02-answer`) |

答えが見たいだけなら `mk quest-02-answer` を使う。
`questions.py` を開くと、これから出る問の答えまで見えてしまう。

## 後片付け

```bash
mk quest-02-reset       # solve.py を白紙に戻す (問題は同じ)
```

`work/` と `data/` ごと消してもよい。次に `mk quest-02` を叩けば作り直される。
