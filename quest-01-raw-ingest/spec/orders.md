# 注文テーブル 取り込み仕様 v1.2

社内の注文データを、下流(BI・集計バッチ)が安心して使える形に整えるための仕様。
**下流はこのテーブルしか見ない。** 生CSVの都合は、ここで吸収しきること。

## 入力

`data/` 配下のCSV **すべて**。ファイルは増える。ファイル名を決め打ちしないこと。

| ファイル | 備考 |
| --- | --- |
| `orders_2024-01-01_2024-01-10.csv` | |
| `orders_2024-01-11_2024-01-20.csv` | |
| `orders_2024-01-21_2024-01-31.csv` | |
| `orders_late_2024-02-02.csv` | 遅れて届いた分。既に届いた注文の**訂正**を含む |

> [!IMPORTANT]
> 送信元のシステムが複数あり、**ファイルによって文字コード・列の並び・値の書式が違う**。
> これは仕様であって、直してもらえる見込みはない。取り込み側で吸収すること。

## 出力

`out/orders.parquet` — **単一のParquetファイル**。ディレクトリではない。

| 列 | 型 | 内容 |
| --- | --- | --- |
| `order_id` | `string` | 注文ID |
| `order_date` | `date32` | 注文日。日付型であること。文字列ではない |
| `customer_name` | `string` | 顧客名。前後の空白は除去する |
| `region` | `string` | 地域。`east` / `west` / `north` / `south` のいずれか(小文字) |
| `status` | `string` | 状態。`completed` / `cancelled` / `pending` のいずれか(小文字) |
| `quantity` | `int32` | 数量 |
| `amount_jpy` | `int64` | 金額。**円単位の整数**。生データの `amount` 列に相当する |

列の並びもこの順にすること。ここに無い列を足さないこと。

## 処理

**この順で処理する。** 順番を入れ替えると結果が変わる。

### 1. すべてのファイルを結合する

### 2. 欠損表現を正規化する

次の値は「欠損」として扱う。値の前後に空白が付いていることがある。

```
NULL    N/A    -    (空文字)
```

### 3. 表記ゆれを吸収する

| 対象 | 生データに現れる形 |
| --- | --- |
| 日付 | `2024-01-05` / `2024/01/05` / `2024年1月5日` |
| 金額 | `1200` / `1200.0` / `1,200` / `￥1,200` / `1,200円` |
| 数量 | `3` / `３`(全角) |
| 地域・状態 | `east` / `East` / `EAST` |
| 顧客名 | 前後に半角空白・全角空白が付くことがある |

### 4. 重複を排除する

同じ `order_id` の行が複数ある場合、**`ingested_at` が最も新しい行だけを採用**する。
`ingested_at` は全行で一意なので、迷うことはない。

`ingested_at` は出力に含めない。ここで使い切る列。

### 5. 除外する

**4のあと**の行に対して、次のいずれかに当てはまるものを落とす。

- `order_date` が欠損
- `quantity` が欠損、または `0` 以下
- `amount_jpy` が欠損

> [!WARNING]
> **除外は重複排除より後**である。
> 「不正な行を先に捨ててから重複排除する」と、訂正で無効になったはずの注文が
> 古い行のまま生き残ってしまう。それは仕様違反。

`customer_name` が欠損の行は**落とさない**。`null` のまま出力する。

### 6. 並べる

`order_id` の昇順。

## 検証

見張り役が10秒ごとに `out/orders.parquet` を検証している。
判定結果は `out/report.txt` に書き出される。

すべて合格している**間だけ** `out/flag.txt` が現れる。
