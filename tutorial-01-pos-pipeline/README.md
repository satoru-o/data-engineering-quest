# tutorial-01: POS売上パイプライン

**汚れた売上ログを、使えるサマリにするまでを、一緒に最後まで作ってみる教材です。**

クエストと違って、解けなくても進めません、ということはありません。
考え方の説明を読んで、セルを上から実行して、小さい練習を1問やる。
その繰り返しで、最後には**自分でパイプラインが書ける状態**になることを目指しています。

## 何を作るのか

みなとストア(3店舗)の4月の売上が、**3つの系統**からバラバラに届きます。

```
旧POS   cp932、全角数字、2024年4月1日、店名は「ミナトストア　渋谷」
新POS   utf-8、列の順番が違う、金額に ￥ とカンマ
EC      utf-8、税抜、返品はマイナス、商品コードの先頭ゼロが落ちている
```

送信元は直してくれません。受け取る側で吸収して、
**日次の売上サマリ**にするところまで持っていきます。

```
生ログ3種
   ↓  01  取り込みと素性調査      1枚にまとめ、何が汚れているかを数える
   ↓  02  クレンジング            表記・欠損・型を整え、使えない行を隔離する
   ↓  03  名寄せと結合            店舗マスタ・商品マスタに突き合わせる
   ↓  04  集計とサマリ            日次 × 店舗 × カテゴリにまとめる
   ↓  05  出力と再実行            Parquetに書き、二度流しても壊れないようにする
日次サマリ
```

## 使い方

```bash
./start.sh
```

http://localhost:8889/lab が開きます。左のファイルブラウザから `01-ingest.ipynb` を開いてください。

```bash
./stop.sh                # 止める
./start.sh --reset       # ノートブックを配り直す (自分の書き込みは消える)
```

| | |
| --- | --- |
| `notebooks/` | 配布用のノートブック。git管理 |
| `work/` | **自分がいじるほう。git管理外** |
| `work/out/` | 05章が Parquet を書き出す先。実行のたびに作り直される |
| `data/` | POSの生データ。読み取り専用でマウントされる |

`start.sh` が `notebooks/` の中身を `work/` に配ります。
**既にあるファイルは上書きしない**ので、書きかけが消えることはありません。

### make でも同じことができる (パイロット中)

この章だけ、同じ操作を `Makefile` にも書いてあります。
**`.sh` と機能は同じ**で、どちらを使ってもかまいません。
`make` を試すために置いているもので、他の章にはまだありません。

```bash
make up      # ./start.sh 相当
make down    # ./stop.sh 相当
make reset   # ./start.sh --reset 相当
make         # 使えるターゲットの一覧
```

`.sh` と違うのは、**入力が変わったときだけイメージをビルドし直す**点です
(`start.sh` は毎回 `docker compose build` を叩いています)。
2回目以降の `make up` はほぼ即座に終わります。

ホストに `make` が要るので、**配布経路は `./start.sh` のまま**です。
`make` が入っていなくても今までどおり進められます。

### VS Code から使う

ブラウザではなく VS Code の Jupyter 拡張で進めることもできます。

1. `work/01-ingest.ipynb` を開く (`notebooks/` ではなく **`work/`** のほう)
2. 右上のカーネル選択 → 「既存の Jupyter サーバー」 → `http://localhost:8889`
   (トークンは空のまま Enter)
3. `Python 3 (ipykernel)` を選ぶ

コードが動くのはコンテナの中なので、ノートブックに出てくる `/data` や `/work` は
そのまま通ります。ホスト側にパスを読み替える必要はありません。

## 進め方

各章はこの形で進みます。

```
### N-1. 見出し
   考え方 (なぜこれをやるのか)
   [コードセル]      ← 実行する
   出力の読み方      ← どこを見るか
   ✍ 書いてみる      ← 1問。直前とほぼ同じことを別の列で
   <details>答え</details>
```

**「書いてみる」は、答えを開いて写してかまいません。** 1文字も自分で思いつかなくても、
写して動かして出力を見れば十分に身に付きます。詰まったまま止まるより先へ進んでください。

各章の最後に、その章でやったことが**関数1つ**にまとまります。
それが次の章の入口になります。

**どの章からでも開けます。** 各章の冒頭で、前の章までの結果を `data/` から作り直しています。

## 収録

| | 章 | 何ができるようになるか | |
| --- | --- | --- | --- |
| 01 | [取り込みと素性調査](notebooks/01-ingest.ipynb) | 文字コードの違うファイルを読む / 列名と列順の違うファイルを1枚に揃える / **手をつける前にデータの素性を数える** | できた |
| 02 | [クレンジング](notebooks/02-clean.ipynb) | 欠損表現の統一 / 全角と空白 / 金額と日付の正規化 / **税込と税抜を揃える** / 使えない行を捨てずに隔離する | できた |
| 03 | [名寄せと結合](notebooks/03-join.ipynb) | 表記の揺れた店名をマスタに寄せる / 結合で行が増える事故を防ぐ / マスタに無いものを見つける | できた |
| 04 | [集計とサマリ](notebooks/04-aggregate.ipynb) | 粒度を決める / 返品とテスト伝票の扱い / 売上ゼロの日を埋める / 検算する | できた |
| 05 | [出力と再実行](notebooks/05-output.ipynb) | Parquetで型ごと保存する / パーティションに分ける / **二度流しても結果が変わらないようにする** | できた |

各章は単独で開けます。冒頭に前章までの答えをまとめたセルがあり、そこから `/data` を読み直します。

### 章をまたぐ名前

同じ語を章によって違う意味で使わないよう、5つの名前を固定しています。

| 名前 | 中身 | 作る章 | 4月の行数 |
| --- | --- | --- | --- |
| `raw` | 3系統を積んだだけ。全部文字列 | 01 | 36 |
| `clean` | 表記と型を整え、使えない行を除いたもの | 02 | 34 |
| `rejected` | 使えないので隔離した行。捨てていない | 02 | 2 |
| `fact` | `clean` にマスタを結合したもの。**除外前** | 03 | 34 |
| `target` | `fact` から集計対象外を除いたもの | 04 | 32 |

`clean` と `fact` の行数が同じであることが、03章の合格条件です(結合で行は増えない)。

## データ

`data/` にあるファイルは**全部目で見られる大きさ**です(明細36行 + マスタ)。
集計結果を手で数えて確かめられる、というのがこの大きさにしてある理由です。

```
sales_2024-04_old.csv    14行   旧POS  (cp932)
sales_2024-04_new.csv    12行   新POS
sales_2024-04_ec.csv     10行   EC     (税抜・返品あり)
sales_2024-05_new.csv     8行   5月分  (05章で使う)
sales_2024-04_fix.csv     2行   4月の訂正 (05章で使う)
shops.csv                 4行   店舗マスタ (1店は閉店済み)
shop_alias.csv            9行   店名の別名辞書
items.csv                 6行   商品マスタ (廃番・カテゴリ欠損あり)
```
